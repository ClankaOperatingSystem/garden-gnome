# The structure of a garden

This doctrine applies to how a garden divides its work among scopes,
projects and tasks.

**STRUCT-1. One outcome to a project.** A project has one outcome. Every
task in it serves that outcome.

**STRUCT-2. One home for a task.** A piece of work is a task in one place.
Other places link to it.

**STRUCT-3. One home for a fact or a rule.** A fact or a rule is stated in
one page. Other pages link to it.

**STRUCT-4. The smallest containing scope.** A task or a project is kept in
the smallest scope that contains everything it touches.

**STRUCT-5. Work with its product.** Work on a product is kept under the
responsibility that owns the product.

**STRUCT-6. No reaching up.** A project does not act on the files of the
scope that contains it. That work is a task of the containing scope.

**STRUCT-7. Rules outlive projects.** A rule in canon does not depend on a
finite project.

**STRUCT-8. A met outcome closes the project.** When a project's outcome is
met, or nothing in it is scheduled, the project is closed or set aside.

**STRUCT-9. A live project moves.** An open project has a next action or a
waiting item, and its review is not past due.

**STRUCT-10. A responsibility has work.** A responsibility owns work or a
product of its own, and is not only a layer above one child.

**STRUCT-11. One event for a shared blocker.** A blocker that several
projects wait on is one event, with a trigger into each project.
